# Обезличенный архив рабочих сессий

Откройте **Рабочие сессии**, создайте сессию и добавьте результаты из анализатора. Обычная сессия остаётся в памяти вкладки: 20 проверок, 4 MiB исходников. Постоянное хранение выполняется отдельно и только по кнопке.

## Сохранение и восстановление

1. Нажмите «Подготовить архив сессии» и проверьте JSON.
2. Подтвердите, что хотите сохранить обезличенный архив в браузере.
3. Нажмите «Сохранить архив». После сообщения об успехе можно перезагрузить страницу.
4. Выберите «Восстановить сессию» у сохранённого архива. При замене текущей сессии приложение запросит подтверждение потери её несохранённых исходников.

Архив сохраняет порядок, время, тип и разрешённые семантические поля проверки. Реальные IP заменяются согласованными маркерами; эквивалентные IPv6 нормализуются. Домены и имена интерфейсов заменяются стабильными именами, значения TXT — стабильными метками текста. Это позволяет сравнивать совпадения и изменения внутри одного архива, не сохраняя исходные значения. Документационные IP остаются открытыми.

UUID и даты остаются метаданными. Исходный текст, название/контекст сессии, метки проверок, MAC, описания, суффиксы, DHCP server, исходные наблюдения/предупреждения и произвольные дополнительные поля исключаются. Неподходящие по размеру/схеме модели дают ошибку, без скрытой потери части проверок.

Архив открывается для просмотра и сравнения. Оригинальные источники недоступны; кнопки просмотра исходника отключены. Новые измерения добавляются в новую сессию: соответствие новых реальных IP старым обезличенным маркерам восстановить нельзя. Старые диагностические выводы автоматически не пересчитываются по замаскированным адресам.

Структурный diff поддерживает все семь форматов. Для PowerShell выбирайте одинаковые cmdlet. Сравнение не подтверждает неизменность неподдерживаемых полей и не устанавливает причину сбоя. Маскированные имена/TXT показывают отношения равенства, а не исходное содержимое.

## Импорт, экспорт и лимиты

«Скачать архив JSON» создаёт один совместимый с импортом файл. Импорт проверяет строгую версию 1, UUID, даты, числовые границы, типы моделей, допустимые маркеры/документационные адреса и отсутствие неизвестных полей. Перед записью есть предпросмотр и отдельная кнопка. Совпадающий UUID обновляет существующий архив.

Лимиты: 2 MiB на JSON, 20 проверок в одном архиве, 20 архивов и 10 MiB общего локального хранилища. Проверка квоты и запись проходят в одной IndexedDB-транзакции. Неудачная запись не оставляет частичного импорта. Учебные сценарии, кейсы, прогресс и архивы находятся в отдельных object stores/базах.

Удаление архива требует подтверждения. Очистка рабочей памяти не удаляет сохранённые архивы. Скачанные файлы и резервные копии браузера управляются отдельно. IndexedDB не шифруется приложением и не синхронизируется между устройствами/origin.

# Опциональный companion: прогресс и учебные объяснения

Основной сайт остаётся статическим. Лаборатории, курсы, локальный прогресс, редакторы и импорт JSON работают без companion. Сервис нужен только для явного переноса прогресса через свою учётную запись и опционального обращения к внешнему AI. Он не запускает ОС, VM, shell или команды терминала.

## Локальный запуск

Используйте Node 22.22+ либо поддерживаемый Node 24, зависимости проекта уже установлены:

```sh
npm run companion
```

В другом терминале:

```sh
npm run dev
```

Откройте **Учебный центр → Практикум развития → Обмен и преподаватель**. Подтвердите адрес `http://127.0.0.1:8787`, задайте вымышленное имя от 3 до 40 символов (`a-z`, цифры, `_`, `-`) и пароль 10–128 символов, создайте учебную учётную запись. Другой пароль для каждого сервиса предпочтительнее повторного использования.

Настройки в `server/companion.env.example` — пример; `.env` автоматически не загружается. Чтобы использовать пример в zsh/bash:

```sh
source server/companion.env.example
npm run companion
```

По умолчанию сервер слушает **только `127.0.0.1`**, порт 8787. Разрешённые web origins — localhost/127.0.0.1 на 5173/4173. Порт и каталог задаются `WORKBENCH_PORT` и `WORKBENCH_DATA_DIR`; CORS — `WORKBENCH_ALLOWED_ORIGINS` через запятую. По умолчанию клиент и CSP разрешают только `http://127.0.0.1:8787` и `http://localhost:8787`. Изменение серверного порта требует соответствующей настройки origin при сборке; для удалённого сервиса используется один точный HTTPS origin без пути, query и встроенных credentials.

Чтобы включить собственный HTTPS-сервис, владелец задаёт адрес **до сборки**:

```sh
VITE_COMPANION_ORIGIN=https://study.example npm run build
```

Для dev аналогично `VITE_COMPANION_ORIGIN=https://study.example npm run dev`. Адрес попадает в точный allowlist клиента и `connect-src` CSP; ввод другого origin отклоняется до запроса. Неверные схемы, credentials, пути, wildcard и CSP-injection останавливают сборку. Переменная содержит публичный адрес, **не ключ**. Обновите CORS сервиса (`WORKBENCH_ALLOWED_ORIGINS`) на origin сайта и настройте собственный HTTPS reverse proxy к loopback-сервису. Если хостинг устанавливает дополнительный HTTP CSP, внесите тот же точный origin и в него: meta-политика не расширяет более строгий HTTP-заголовок.

Для HTTPS-сайта доступ к локальному HTTP зависит также от политики браузера. Проверяйте companion вместе с локальным dev/preview. Внешний HTTPS-адрес требует собственной инфраструктуры и тестирования; она здесь не развёрнута. Сервис не входит в статический `dist/` и не публикуется GitHub Pages workflow.

## Перенос прогресса

1. Нажмите **«Прочитать прогресс с сервиса»**.
2. Сравните локальный и серверный JSON, количество попыток и ревизию.
3. Выберите загрузку с заменой локальной версии либо отправку с заменой серверной.
4. При `409` перечитайте новую серверную ревизию и сравните содержимое снова. Автоматического объединения результатов нет.
5. Выход закрывает локальный токен. Если сервис уже недоступен, интерфейс всё равно отсоединяется; серверный сеанс истечёт через 6 часов.

Передаётся только прогресс практикума: ID, навыки, оценки, режимы, подсказки, даты, варианты, отметки уроков и направление. Логи, исходный анализатор, история команд, свободные заметки портфолио, кейсы и авторские лаборатории не отправляются. Автосинхронизации и фоновых запросов нет. При отсутствии сети сохраняются локальные функции и ручной JSON.

## API и хранение

| Метод  | Маршрут          | Назначение                                         |
| ------ | ---------------- | -------------------------------------------------- |
| GET    | `/api/health`    | Версия контракта и доступность AI                  |
| POST   | `/api/accounts`  | Создать учебную учётную запись                     |
| POST   | `/api/login`     | Получить bearer token                              |
| POST   | `/api/logout`    | Отозвать текущий сеанс                             |
| GET    | `/api/progress`  | Получить состояние и ревизию                       |
| PUT    | `/api/progress`  | Строгий JSON, обязательный `If-Match`              |
| DELETE | `/api/account`   | Удалить пользователя, его прогресс и сеансы        |
| POST   | `/api/assistant` | Локальное либо явно запрошенное внешнее объяснение |

SQLite `user_version=1`, неизвестная будущая версия отклоняется. Файл `.workbench-data/companion.sqlite` создаётся с правами 0600, новый каталог — 0700. При использовании уже существующего каталога его права определяет владелец. Пароли — scrypt с отдельной солью; токены случайные, на сервере хранится их SHA-256. Токен и пароль в браузере остаются только в памяти компонента; уход из раздела закрывает клиент. Сеансы ограничены 6 часами и 10 активными токенами на пользователя.

Пределы: JSON 256 KiB, 500 попыток на прогресс, 100 учётных записей, 80 запросов в минуту на IP, 10 внешних AI-запросов в час на пользователя. Ограничение запросов хранится в памяти процесса и сбрасывается при перезапуске. Право чтения/записи прогресса ограничено текущим пользователем; условная запись выполняется в SQLite-транзакции. Неизвестные поля отклоняются. API не принимает произвольные SQL/скрипты.

Это companion для собственного учебного использования. Публичный многопользовательский сервис потребует отдельно HTTPS/reverse proxy, операционного резервирования, восстановления доступа, управления регистрацией, ролей преподавателя, контроля зависимостей и нагрузки. Роли класса здесь заменены ручным обменом пакетами и обезличенным обзором навыков; такой обзор не является независимой аттестацией.

## Резервирование и удаление

Закройте сервис через Ctrl+C, дождитесь завершения процесса, затем скопируйте **закрытую** SQLite-базу в свой приватный каталог. Не копируйте только основной файл работающей WAL-базы. Для проверки восстановления используйте копию базы в отдельном `WORKBENCH_DATA_DIR`, пока исходный сервис остановлен, на обычном порту 8787; войдите учебной записью, сравните прогресс и ревизию. Оригинал сохраняйте до окончания проверки. Резервная копия содержит хэши паролей и учебные данные; не включайте её в Git.

Удаление учётной записи выполняется отдельной подтверждающей кнопкой. Локальный прогресс и выгруженные файлы оно не удаляет. Резервные копии и другие созданные ранее файлы удаляются владельцем отдельно.

## Опциональный AI

Локальная кнопка объяснения читает курсы и работает без сервера/сети. Внешний вариант требует отдельно настроенных на сервере `OPENAI_API_KEY` и `WORKBENCH_AI_MODEL`. Секрет не встраивается в браузерный bundle. Не записывайте ключ в отслеживаемый пример env.

Клиент показывает вопрос и открытые материалы перед отправкой и требует отдельную отметку согласия. Сервер отправляет выбранный курс и вопрос в OpenAI Responses API с `store: false`, ограничением ответа и тайм-аутом. Рабочие логи и портфолио не присоединяются; пользователь должен проверить собственный вопрос на чувствительные данные. `store: false` не обещает отсутствие всех форм хранения провайдером. Модель, доступ и стоимость выбирает владелец по актуальным условиям своего аккаунта.

Ответ отображается как текст, источник ограничен HTTPS. AI не меняет оценку лаборатории, не исполняет инструменты и может ошибаться. API-контракт проверен имитацией ответа; реальный запрос провайдеру не выполнялся.

[Официальная документация Responses API](https://developers.openai.com/api/docs/guides/migrate-to-responses), [Node SQLite](https://nodejs.org/docs/latest-v22.x/api/sqlite.html).

## Проверки

```sh
npm run test:companion
npm run test:coverage
```

Интеграционные тесты используют временную SQLite в памяти и локальный HTTP: CORS, вход, изоляция пользователей, CAS-ревизии, границы схемы, выход/удаление, локальные материалы, отключённый AI и mocked Responses contract. Живая проверка внешнего провайдера и публичное развёртывание в этот набор не входят.

## Эксплуатационные исправления — 0.6.0

Некорректный request-target даёт ограниченный 400; после него процесс обслуживает health и авторизованные запросы. Пароль вычисляется асинхронным scrypt, одновременно не более двух вычислений; при заполнении capacity возвращается 503 и можно повторить позже. Ошибки origin/AI-конфигурации названы явно. Предел API 256 KiB сохранён; крупный прогресс переносится через общий JSON, клиент проверяет размер до отправки.

Для копирования SQLite используйте отдельный CLI. Копия проверяет integrity, внешние ключи, версию и payload прогресса. Восстановление проверяет SHA-256, создаёт новый файл и удаляет старые сеансы в восстановленной БД. Исходная БД и существующие пути не перезаписываются. Файлы копии содержат учётные данные и учебный прогресс; храните их как приватные данные.

```sh
node server/companion-backup.mjs backup .workbench-data/companion.sqlite /PATH/NEW_COPY.sqlite
node server/companion-backup.mjs verify /PATH/NEW_COPY.sqlite
# Остановите companion перед переключением на восстановленную БД.
node server/companion-backup.mjs restore /PATH/NEW_COPY.sqlite /PATH/NEW_DATABASE.sqlite
```

Сохраняйте SQLite и файл `.sha256.json` вместе. Прежде чем вручную переключить путь сервиса, проверьте restored DB и сохраните прежнюю. Эти операции не запускаются через браузер; companion не получает API исполнения команд.

Ссылка у объяснения относится к переданному материалу курса, а не удостоверяет весь ответ AI. Оценка лаборатории вычисляется детерминированно отдельно. Источники: [асинхронный scrypt](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback), [SQLite backup](https://nodejs.org/api/sqlite.html#sqlitebackupsource-db-path-options); API просмотрены 10.10.2026.

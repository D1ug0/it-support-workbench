# Как использовать Workbench для развития

## Первое знакомство

1. На главной выберите «Не знаю, что проверять». В помощнике укажите симптом, масштаб и контекст. Если факт неизвестен, выберите «Пока не знаю».
2. Прочитайте цель первого шага. Выполните проверку вручную и отметьте действие. Отметка не означает успешный результат.
3. Перейдите в анализатор из нужного шага. Инструкция «Как получить вывод команды в Windows?» помогает подготовить текст. Начните с блока «Коротко о результате» и проверьте исходные строки.
4. Вернитесь в помощник через меню: ответы и отметки сохраняются при переходах. Скачайте план перед перезагрузкой, если он нужен дальше.
5. В учебном центре следуйте маршруту «прочитать → проверить → применить». Разберите последнюю ошибку прежде, чем переходить к следующей теме. В инструментах решите задания по подсетям, затем сравните объяснение.

Словарь доступен в анализаторе и справочнике. Ctrl/⌘+K находит разделы, знания и термины. При переходе к учебному примеру существующий текст не заменяется автоматически.

## Первый практический цикл

1. Разберите демопример. Для каждого наблюдения найдите исходную строку и прочитайте ограничение: что подтверждено, что требует проверки.
2. Создайте сессию с вымышленным устройством. Добавьте ipconfig, nslookup и ping из примеров. Укажите время. Проверьте, согласуются ли DNS-сервер и адрес цели.
3. Измените копию синтетического ipconfig: DNS, IPv4 или шлюз. Разберите и добавьте как «после». Выберите две проверки одной команды, изучите diff и скачайте отчёт.
4. Выберите чек-лист DNS/сети. Отмечайте только разобранные шаги. Экспортируйте его и сравните действия с источниками справочника.
5. Пройдите учебный инцидент и тест по теме. Повторите ошибки после чтения объяснений. Для истории включите сохранение прогресса и сделайте JSON-копию.

Используйте навигацию приложения. Перезагрузка очищает диагностику; офлайн-кэш не сохраняет её источники.

## Темы и упражнения

| Тема        | Практика                           | Что уметь объяснить                                     |
| ----------- | ---------------------------------- | ------------------------------------------------------- |
| Сети        | Echo Reply, timeout, unreachable   | Почему ICMP не доказывает работу HTTPS                  |
| DNS         | Сопоставить ipconfig/nslookup/ping | Сервер, запрос и ответ — разные поля                    |
| DHCP        | APIPA и отключённый адаптер        | Почему признаки дают гипотезу, а не диагноз             |
| Подсети     | /24, /31, /32; выбор маршрута      | Длинный префикс перед низкой метрикой                   |
| Windows     | Update/принтер/VPN                 | Факты и безопасная проверка перед изменением            |
| Методология | Пройти инцидент без угадывания     | Контекст, масштаб, evidence, гипотеза, документирование |

## Коллекция кейсов

Сохраняйте обезличенные отчёты с понятными названиями. Для «до/после» используйте модели сессии; постоянные кейсы — текстовые отчёты. Экспортируйте все части архива. Импорт сначала показывает предпросмотр.

Реальные выводы используйте при разрешении на работу с ними. Проверяйте отчёт перед передачей: маскирование не гарантирует удаления любой чувствительной информации.

## Офлайн и данные

Выполните `npm run build`, затем `npm run preview`. При наличии сети включите офлайн в настройках. После этого доступны анализатор, локальные описания справочника, чек-листы, вопросы и сценарии. Внешние ссылки на документацию требуют сети.

Обновление не перезапускает работу автоматически. Экспортируйте результаты и закройте вкладки для активации новой версии. Кейсы и прогресс удаляются в своих разделах; память диагностики/сессии и офлайн-кэш очищаются отдельно в настройках.

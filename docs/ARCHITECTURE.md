# Архитектура

Vue 3 + TypeScript strict, Vite, Pinia, Vue Router hash, Tailwind CSS 4. Иконки из актуального официального пакета `@lucide/vue` (преемник `lucide-vue-next`). Node 22 LTS указан в `.nvmrc` и CI. Точные версии зафиксированы в lockfile.

## Границы

`pages/components → Pinia/application → parser registry → typed model → rules → report`

Парсеры и правила — чистые функции без Vue, DOM, HTTP и хранилища. `analyzeOutput` объединяет валидацию, обнаружение формата, парсинг и правила. Время передаётся аргументом для воспроизводимых проверок. UI запускает этот сценарий в отдельном module Web Worker. Очистка или редактирование текста прекращает старый worker, поэтому устаревший результат не появляется в новой сессии.

DOM содержит максимум 80 строк источника за раз. Evidence viewer открывает окно вокруг выбранной строки. Лимиты: 2 MiB UTF-8 текста, 50 000 нормализованных строк. Превышение даёт явный отказ, без скрытого обрезания. Номера исходных строк 1-based; нормализация меняет только BOM и переносы.

Для больших результатов есть постраничный просмотр: 12 адаптеров, 20 наблюдений или 80 ответов/маршрутов на страницу. Пагинация меняет только представление: модель и отчёт содержат все разобранные значения. Чтение файла отменяется логически при очистке, новом вводе и уходе со страницы; завершившийся старый Promise не восстанавливает данные.

## Дополнительные модули

- Помощник — чистый `features/guide/catalog.ts`: статические проверяемые ответы → адаптированный план → Markdown. `useGuideStore` сохраняет ответы/отметки между маршрутами в памяти; постоянного хранилища нет.
- `explainResult` создаёт краткое объяснение из типизированной модели и существующих правил. Использует диапазоны исходника, не меняет результат парсера и не добавляет диагноз.
- Учебный маршрут — чистый `features/learning/path.ts`, производное представление прежнего `LearningProgress` v1. Ошибки получают приоритет, затем выбирается следующая тема; миграция не требуется.
- Практика подсетей — 8 фиксированных упражнений на документационных адресах. `subnetPractice.ts` использует существующий CIDR-калькулятор, валидирует ответ до оценки; счётчики отдельные, живут в компоненте.
- Словарь — локальные 24 термина, раскрываемая панель и поиск. Query-параметры содержат только выбранный контекст. Неизвестные команды/ID игнорируются; пример загружается явно, существующий диагностический текст не заменяется переходом.

- `ParsedOutput` — discriminated union семи форматов. У каждой команды собственные парсеры и правила.
- `domain/network.ts` — IPv4/IPv6 validation и CIDR. `/31` следует семантике point-to-point, `/32` — один адрес.
- Справочник — локальный каталог с первичными источниками, датой проверки, командами и ограничениями. Поиск работает без HTTP.
- Тренажёр — версионируемый JSON, Zod schema и чистый движок. Корректный выбор продвигает сценарий, повторный выбор не добавляет баллы. Результаты синтетические.
- Кейсы — отдельный Dexie repository. Явное сохранение обезличенного отчёта. Импорт проверяется строгой схемой; лимиты и upsert выполняются в одной IndexedDB-транзакции.
- Сессии — отдельный Pinia store в памяти, snapshots моделей и источников, пользовательский контекст/время. Чистые функции выполняют корреляцию и семантическое сравнение семи форматов.
- Учебный центр — 30 базовых вопросов и 32 решения продвинутых лабораторных, чистые immutable updates прогресса, строгая import schema, отдельный Dexie repository. Записи сериализуются очередью; нет сохранения без opt-in.
- Чек-листы — локальный каталог шести последовательностей, отметки в памяти, чистый Markdown-export.
- Выбор маршрута — чистая IPv4-функция, longest-prefix match перед metric, несколько равных кандидатов сохраняются. Реальная маршрутизация Windows не выполняется.
- Офлайн — генератор `scripts/build-offline.mjs` строит allowlist файлов сборки и versioned Service Worker. Регистрация только после действия пользователя в production.
- Глобальный поиск — native dialog, клавиатура и навигация к разделам/фильтрованному справочнику.

Хранилище кейсов подключается лениво. Открытие анализатора и ввод текста не создают автосохранение. Названия кейсов и импортированный отчёт — недоверенные строки; Vue выводит их как текст. Семантическое сравнение использует модели рабочих сессий; текстовые кейсы сравниваются рядом без попытки восстановить модель из Markdown.

Сессия ограничена 20 проверками и 4 MiB исходников. Корреляция выбирает последние модели по введённому времени, предупреждает об интервале >30 минут и показывает ограничения интерпретации. IPv6 приводится к канонической форме. Интерфейсы сопоставляются по уникальному точному имени; дубликаты дают явную неоднозначность. Строка маршрута сравнивается целиком, сохраняя связь сети, шлюза, интерфейса и метрики. Разные типы команд нельзя сравнивать как до/после.

Service Worker принимает только GET к allowlist на собственном origin и без query. Hash навигации нормализуется. `ignoreVary` применяется только к статическим файлам из allowlist: сервер может добавлять `Vary: Origin`, а install-fetch и module-fetch используют разные headers. Cache version включает содержимое сборки и код генератора. Install атомарно загружает весь набор; при отказе удаляет незавершённый кэш. Activate удаляет старые кэши только текущего scope. Обновление не использует `skipWaiting` и не перезагружает страницы.

## Решения

Учебный терминал — отдельная виртуальная среда, описанная в [TRAINING_TERMINAL.md](TRAINING_TERMINAL.md). Чистый движок моделирует DNS, кэш и доступность ICMP/TCP; xterm.js отвечает за отображение. Вывод проходит существующий `analyzeOutput` и `compareOutputs` в отдельном store, не заменяет рабочие сессии. Контрольные точки проверяются строгой схемой и сохраняются только явно. Прогресс использует прежнюю v3 с зарегистрированными TERM-ID; прежний журнал сохраняет v3, а новая карта навыков использует независимую схему практикума v1.

- Основное приложение статическое и работает в браузере; отдельный опциональный companion хранит прогресс и объяснения. Доступа к системным командам нет.
- Hash routes и относительный Vite `base: './'` для размещения в подпапке.
- Детерминированные правила: степень уверенности относится к интерпретации признака.
- Недостающие значения остаются неопределёнными; модель не подставляет фиктивные адреса.
- Чувствительный ввод по умолчанию живёт только в памяти. Тема также не сохраняется.
- Opt-in кейсы хранят обезличенный отчёт, тип, UUID, дату и название; исходник туда не попадает. Очистка анализатора и удаление кейсов — отдельные действия.
- Источники сессии остаются в памяти после очистки анализатора; настройки предлагают явную очистку обеих областей.
- Учебный прогресс сохраняет счётчики и ID, не диагностические данные. Отключение записи не удаляет историю; для удаления есть отдельное подтверждение.
- Экспорт кейсов разбивается на файлы до лимита импорта 2 MiB; каждый файл отдельно проходит существующую schemaVersion 1.
- Экспорт использует разрешённый список семантических полей, исключая все произвольные имена, описания и исходные строки. Недокументационные IP заменяются согласованными маркерами.
- Сырой отчёт — только после отдельного подтверждения в предпросмотре.
- Meta CSP — частичная защита для статического хостинга; полноценные HTTP headers зависят от хоста.
- Публикация вручную через workflow_dispatch после всех проверок. Так исходный локальный проект не публикуется без решения владельца.

## Расширение

Продвинутый курс — `features/academy/catalog.ts`: восемь модулей с теорией, командами, источниками и 32 фиксированными решениями. `lab.ts` проверяет принадлежность заданий, фиксирует первый выбор, учитывает уникальные подсказки и формирует Markdown. UI хранит текущую попытку в памяти; завершённая лабораторная записывает итог через существующий learning store. Тип консоли передаётся в `CopyCommand` явно, включая `Resolve-DnsName`.

Учебный прогресс v3 добавляет `journal` и `weeklyGoal` к ответам, оценкам и `reviews`. Zod принимает v1/v2 и преобразует их в v3 без вымышленных событий; Dexie использует прежний object store, так как индекс `id` не изменился. Импорт проверяет объединённый каталог базовых/продвинутых вопросов и ID лабораторных. `review.ts` рассчитывает сроки из переданного времени, не увеличивает серию при раннем повторении и строит подборку только из отвеченных вопросов. UI обновляет часы раз в минуту и освобождает таймер при уходе. Запись остаётся opt-in; диагностические данные в прогресс не включаются.

Новый формат получает собственную модель, `detect/parse/analyze`, синтетические fixtures и тесты. Сетевые проверки не выполняются приложением. Не переносите parsing regex в Vue-компоненты.

Новый сценарий требует `schemaVersion: 1`, уникальных ID шагов/действий, существующего рекомендованного выбора и теста полного прохождения. Изменение схемы кейсов требует явной миграции; неизвестная версия отклоняется.

## Практикум и архивы

`practice/catalog.ts` содержит 24 упражнения и чистую проверку формат/результат. Компонент фиксирует первую валидную отправку и записывает только ID/оценку через learning store. `learning/journal.ts` рассчитывает локальную неделю из UTC-дат, учитывает последние 500 событий и исключает будущие записи. Версия payload прогресса изменена на 3; индекс Dexie `id` сохраняет совместимость хранилища.

`simulator/custom.ts` проверяет строгие линейные сценарии и namespace USR-UUID; `customRepository.ts` читает квоту и выполняет запись атомарно. Редактор переиспользует существующий engine. Ошибки не пропускают этап, повторное действие не начисляет дополнительный штраф. Схема не допускает ссылки на несуществующее или небезопасное рекомендуемое действие.

`parser/extendedParsers.ts` создаёт отдельные DNS/PowerShell модели. JSON использует явные поля; текстовый DNS распознаёт полные блоки. Номера объектов относятся к физическим строкам источника, включая вложенные JSON-объекты. Registry, rules, explanations, diff и report поддерживают новые discriminant-значения; parserVersion — 1.2.0.

`sessions/archive.ts` строит новое безопасное представление каждой модели из разрешённых полей. Имена, адреса и TXT получают стабильные маркеры в границах архива; общая таблица замен не сохраняется. Строгая схема не разрешает импорт исходного текста/реальных имён. `archiveRepository.ts` контролирует лимит количества и байтов в транзакции. Восстановление создаёт partial-модели без источников и исходных findings: правила IP не запускаются на маскированных значениях. UI запрещает смешивание восстановленного архива с новыми реальными измерениями.

## Практикум 0.4.0

`networkModel.ts` задаёт строгую декларативную топологию и состояние, чистые выбор маршрута/разрешение имени/оценку. `networkEngine.ts` применяет ограниченные командные переходы к копии состояния, генерирует вывод и временную линию; `NetworkMap` читает то же состояние. Аудит сравнивает нарушенные условия до/после, сохраняет ограниченные счётчики и влияет на оценку. Стек последних 20 состояний для отката хранится только в RAM; откат сохраняет время/evidence/аудит и требует повторной проверки. Первые три задания сохраняют прежний движок. Checkpoint v2 принимает прежний v1 и проверяет связь основной и сетевой ревизий.

`workshop/skills.ts` отделяет чтение, вопрос и самостоятельные варианты; `courses.ts` содержит тематические пакеты, `graph.ts` проверяет достижимость/завершение развилок, `traces.ts` ограничивает временную линию, `portfolio.ts` формирует отчёты из явных заметок. Отдельный Pinia store и Dexie DB хранят прогресс/лаборатории/графы/отчёты с лимитами. Прежняя v3 не мигрируется в выдуманные навыки. Очередь и проверка ревизии блокируют устаревшую запись прогресса другой вкладкой; локальный флаг предотвращает возобновление записи после быстрого reload.

Ленивый практикум входит в статический офлайн-пакет. Service Worker отвечает только на запрос версии пакета через MessageChannel; он не кеширует API и не применяет обновление автоматически. Глобальный поиск подгружает новые курсы/заголовки явных локальных сохранений по открытию поиска.

`server/companion.mjs` — отдельный опциональный Node/SQLite процесс с auth/CORS/лимитами/CAS. Общая Zod-схема прогресса используется сервером и браузером. Клиент не делает запросов на mount, держит bearer в памяти и отменяет запросы при уходе. AI-adapter вызывается только отдельно, получает открытый курс и подтверждённый вопрос, не связан с оценкой. [Контракт и эксплуатация](COMPANION.md). Репозиторий не содержит автоматически запускаемого агента ОС.

Авторские курсы: `customCourses.ts` содержит строгую схему и проверку ссылок, `CourseEditor` обеспечивает JSON/preview/consent/import/export. Dexie-база практикума v2 наследует коллекции v1 и добавляет courses без удаления прежних данных. Встроенные материалы отделены от COURSE-ID; авторский вопрос не меняет assessment. Ссылки проверяются в транзакции courses/labs; удаление используемой лаборатории отклоняется.

CSP формируется Vite-плагином для dev/build из точных loopback origins и одного проверенного `VITE_COMPANION_ORIGIN`. Тот же список применён клиентом до запроса. Production CSP исключает dev WebSocket. Service Worker кэширует только собственные статические ресурсы; внешние API не входят в allowlist.

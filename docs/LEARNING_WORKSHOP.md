# Практикум: от теории к самостоятельной диагностике

Откройте **Учебный центр**. Базовая часть содержит четыре режима: базовые темы, продвинутый курс, самостоятельная практика и журнал обучения. Практикум 0.6.0 с терминалом, картой навыков, редакторами и портфолио описан в [WORKSHOP_GUIDE.md](WORKSHOP_GUIDE.md). Материалы и задания работают без аккаунта; команды выполняются пользователем в согласованной учебной Windows-среде.

## Как заниматься

1. Изучите одну базовую тему и проверьте понимание тестом.
2. Откройте связанный продвинутый модуль: TLS/HTTP, DNS, AD/Kerberos, SMB, GPO, IPv6, VPN или Wi-Fi. Прочитайте свидетельства лабораторной, выберите проверки и объясните ошибки.
3. Перейдите в **Самостоятельную практику**. Здесь ответ вводится самостоятельно: приложение проверяет расчёт или полный порядок шагов. Объяснение появляется после первой корректно оформленной попытки.
4. Пройдите учебный инцидент в **Тренажёре**, затем создайте собственный в **Редакторе инцидентов**.
5. В **Журнале обучения** задайте цель на неделю и посмотрите результаты. Возвращайтесь к вопросам по расписанию повторений.

Занятие удобно строить вокруг одного вопроса: какие факты уже есть, что они не доказывают и какая проверка различит гипотезы. Оценка задания показывает результат конкретной попытки; она не удостоверяет профессиональную квалификацию.

## 24 самостоятельных задания

| Направление              | Что тренируется                                                                          |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| Подсети, 8 заданий       | Сеть, broadcast, число хостов, маска, wildcard, первый/последний хост и /31              |
| Расчёты, 6 заданий       | ICMP payload, MTU по пробе, необходимый префикс, остаток TTL, порт LDAP/SRV, доля потерь |
| Интерпретация, 3 задания | Выбор SRV target, longest-prefix шлюз, тип DNS для IPv6                                  |
| Планы, 7 заданий         | Порядок проверок TLS, DNS, AD, SMB, GPO, DHCP и VPN в заданных условиях                  |

Формат IPv4 проверяется строго. Числовой ответ — целое число без единиц. Текст регистронезависим, конечная точка домена допустима. План вводится номерами всех шагов, например `2, 1, 4, 3`; пропуски и повторные номера не принимаются.

Неверный формат не создаёт попытку. После первой валидной отправки результат фиксируется; новая попытка начинается отдельной кнопкой. Подсказка доступна до ответа. Разбор можно скачать в Markdown, включая собственный ответ; он не записывается в учебный прогресс.

Планы зависят от условий конкретной задачи. Они не навязывают один порядок для любой реальной неисправности. Например, доказанная зависимость DNS → SRV → TCP → аутентификация в учебном случае не означает, что любой инцидент начинается с DNS.

Задания доступны через Ctrl/⌘+K и прямые ссылки вида `/#/learning?view=practice&task=mtu-payload`.

## Журнал и цель недели

Событие содержит ID, тип, дату UTC и оценку. Журнал учитывает ответы на вопросы, завершённые лабораторные и инциденты, самостоятельную практику. В нём нет введённых ответов, логов или пользовательских текстов сценария.

Хранятся последние 500 событий. Активность рассчитывается по ним: неделя начинается в понедельник по местному времени устройства; будущие события из импорта не входят в текущий результат. Успешность — доля попыток с оценкой не ниже 70. Цель — от 1 до 200 действий за неделю. Кнопка «Обновить период» обновляет расчёт на долго открытой странице.

История фильтруется и отображается по 20 событий. Доступен Markdown-экспорт. Для постоянного хранения включите общий переключатель учебного прогресса и дождитесь сообщения о завершении записи.

Прогресс v1/v2 автоматически переводится в v3: счётчики, оценки и существующее расписание сохраняются. История старым ответам не придумывается; журнал начинается с новых событий. Прогресс можно экспортировать/импортировать в JSON до 256 KiB. Предыдущие версии приложения v3 не понимают.

## Собственные инциденты

Откройте **Тренажёр → Редактор инцидентов**. Начните с пустого сценария или копии встроенного. Заполните симптом, учебные данные, критерий восстановления и этапы. Каждый этап содержит вопрос, 2–5 действий, их синтетические результаты и объяснения.

Выберите безопасное обоснованное действие. Оно переводит к следующему этапу. Ошибка остаётся на текущем этапе; повторное нажатие того же действия не добавляет штраф. Этапы можно перемещать выше/ниже. Завершение фиксирует оценку в общем учебном прогрессе.

Схема проверяет уникальные ID, ссылки на рекомендуемые действия, их безопасность, 1–10 этапов и длину полей. Модель линейная; редактор произвольного графа с развилками ещё не реализован.

Сохранение происходит только по кнопке после подтверждения учебных данных. Встроенные сценарии не перезаписываются. Лимиты: 20 собственных сценариев, 64 KiB на один, 1 MiB всего. JSON-файл импорта — до 2 MiB; сначала показаны названия и число этапов, затем отдельное подтверждение записи. Совпадающие пользовательские UUID обновляются атомарно. Для обмена скачайте JSON сценария.

Свободный текст автоматически не обезличивается. Используйте `lab.example`, документационные сети и вымышленные системы. Приложение не проверяет научную корректность авторского объяснения: она остаётся ответственностью автора.

В справочник добавлены материалы о SRV, MX/TXT/TTL, Path MTU и границах TCP-проверки; всего 22 карточки и 24 термина с примерами. Источники: Microsoft Learn и RFC Editor.

## Анализ PowerShell и типизированного DNS

В анализатор добавлены nslookup MX/TXT/SRV и JSON выбранных полей `Resolve-DnsName`, `Test-NetConnection`, `Get-NetIPConfiguration`. Разверните инструкцию получения вывода: там есть готовые команды экспорта через `ConvertTo-Json` и семь новых примеров.

Практикуйте разделение данных DNS и доступности сервиса. Проверка TCP отвечает на вопрос о соединении с портом в момент измерения; она не проверяет TLS, HTTP и права доступа. MX preference, SRV priority/weight/port и секция DNS сохраняются отдельно. TXT может содержать чувствительные значения и скрыт по умолчанию.

Точные форматы, поля и ограничения: [PARSERS.md](PARSERS.md). Архивирование последовательности проверок: [SESSION_ARCHIVE.md](SESSION_ARCHIVE.md).

Новые события связаны через UUID с единым учебным входом. Прежние результаты и расписания остаются совместимыми, без выдумывания прошлых событий. Линейные авторские инциденты теперь входят в общий backup v2.

# Приём настоящих Windows fixtures

Сейчас `src/fixtures/real/manifest.json` пуст: настоящая Windows VM недоступна. Синтетические fixtures не переименованы в реальные. `npm run test:fixtures:real` возвращает код 2, пока нет разрешённых проверенных captures; это не успешное подтверждение совместимости.

## Сбор на своём стенде

В изолированной Windows VM вручную запустите `scripts/collect-windows-fixtures.ps1` с новым локальным каталогом, именем и адресом разрешённого учебного сервиса. Скрипт не меняет сетевые настройки, группы или службы; выполняет диагностические сетевые запросы только к заданному ресурсу. Выводы остаются локальными. Сам скрипт пока не проверен в Windows.

```powershell
.\scripts\collect-windows-fixtures.ps1 -OutputDirectory C:\lab-captures\run-01 -LabName portal.lab.example -LabAddress 192.0.2.20 -Port 443
```

Адреса в примере являются обозначениями документации: замените их адресами реально доступного собственного стенда. Сначала снимите минимальный рабочий вывод, затем отдельно известный проблемный случай (например, DHCP/APIPA, DNS timeout, отказ TCP). Не смешивайте команды. Повторите для каждой реально доступной ОС/build, PowerShell и RU/EN локали. Не меняйте рабочие системы ради fixtures.

Сбор сохраняет UTF-8 JSON выбранных полей и CMD текст, плюс версию ОС/build, PowerShell, локаль и время. В PowerShell 5.1 и 7 вывод проверьте визуально: кодировка native CMD зависит от окружения. Ошибка Resolve-DnsName сохраняется отдельно и не выдаётся за поддержанный DNS JSON. `ConvertTo-Json` документирован [Microsoft](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/convertto-json).

## Ручная подготовка

1. Просмотрите raw локально. Удалите реальные имена пользователей/организаций/машин, домены, MAC, DNS suffix, TXT, пути, идентификаторы и секреты. Согласованно замените адреса документационными сетями, сохраняя префиксы, отношения подсетей и диагностическую причину. Скрипт этого автоматически не гарантирует.
2. В репозиторий добавляйте **только обезличенный** файл в `src/fixtures/real/`, без подкаталогов. Сохраните локально исходную контрольную сумму/происхождение для своей проверки; raw в Git не добавляйте.
3. Добавьте запись manifest: `id`, `provenance: real-redacted`, `file`, `expectedFile`, `sha256` обезличенного UTF-8 файла, `os: {name, version, build}`, `shellVersion`, `locale: ru-RU|en-US`, `capturedAt`, `command`, точную `invocation`, `scenario: minimal|problematic`, `reviewed: true`, `ownEnvironment: true`, `redactionNotes`.
4. Отдельный expected JSON содержит `{status, kind, value, warnings, findings}`: полный ожидаемый структурированный результат парсера (либо null), коды предупреждений и ruleId находок. Критерии установите вручную по известному состоянию стенда, затем сравните с парсером. Нельзя слепо записывать текущий ответ парсера как эталон.
5. `npm run test:fixtures:real` проверит схему, пару minimal/problematic для каждой команды/ОС/build/PowerShell/локали, sha256, явные утечки и точные результаты. Проверка утечек лишь дополнительная: ручной просмотр остаётся обязательным.

Матрица подтверждается только для перечисленных captures и их формата. Наличие настоящего fixture не утверждает поддержку всех сборок Windows, локалей, полного AccessCheck или произвольного CIM JSON. Личные данные пользователя не попадают в учебные материалы автоматически.

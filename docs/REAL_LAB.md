# Собственный Windows/Linux-стенд

Workbench работает без виртуальной машины. Этот маршрут предназначен для будущей практики на настоящей ОС; VM и реальные Windows fixtures пока не созданы. Встроенный терминал моделирует ограниченные команды, а анализатор читает предоставленный текст. Companion не исполняет команды на компьютерах.

## Подготовка

1. Выберите гипервизор и разрешённый образ, совместимые с архитектурой компьютера. На Apple Silicon отдельно проверьте поддержку ARM-гостя и нужных компонентов; не считайте x64/ARM взаимозаменяемыми.
2. Создайте Windows 10/11 либо Windows Server и Linux VM. Начните с одной VM; AD требует отдельного учебного сервера и клиента. Используйте вымышленные учётные записи и данные.
3. Для упражнений выделите отдельную виртуальную сеть, например `172.20.10.0/24`, Windows `172.20.10.10`, Linux `172.20.10.20`. Связь с интернетом для установки обновлений настройте отдельно. Документационные адреса встроенных лабораторий не являются готовой конфигурацией реальной сети.
4. Запишите адреса, префиксы, шлюз, DNS, назначение интерфейсов, ОС и локаль. Убедитесь, что учебная сеть не пересекается с вашей LAN/VPN.
5. Сделайте снимок исправного состояния. Отдельно экспортируйте нужные учебные файлы; снимок зависит от исходного хранилища и не заменяет проверенную резервную копию.
6. Меняйте по одному условию через консоль гостевой VM. Перед следующим заданием восстановите снимок и проверьте исходное состояние.

## Получение исходных данных Windows

Выполняйте следующие команды **внутри своей учебной Windows VM**. Это чтение состояния; оно может содержать имена компьютеров, доменов, адреса и идентификаторы.

CMD:

```bat
ipconfig /all
ipconfig /displaydns
route print
ping <адрес-учебного-сервера>
nslookup <имя-учебного-сервиса>
tracert <адрес-учебного-сервера>
```

Для PowerShell используйте выбранные поля, а не произвольную таблицу `Format-List`:

```powershell
Get-NetIPConfiguration | Select-Object InterfaceIndex, InterfaceAlias, IPv4Address, IPv6Address, IPv4DefaultGateway, DNSServer | ConvertTo-Json -Depth 4
Test-NetConnection -ComputerName <имя-учебного-сервиса> -Port 443 | Select-Object ComputerName, RemoteAddress, RemotePort, InterfaceAlias, SourceAddress, TcpTestSucceeded | ConvertTo-Json -Depth 4
Resolve-DnsName <имя-учебного-сервиса> | Select-Object Name, Type, TTL, Section, IPAddress, NameHost, NameExchange, Preference, Strings, NameTarget, Priority, Weight, Port | ConvertTo-Json -Depth 4
```

Не объединяйте результаты разных команд в один файл. JSON сохраняйте в UTF-8: в Windows PowerShell 5.1 `Out-File -Encoding utf8` добавляет BOM, который анализатор поддерживает. UTF-16LE не поддерживается. Для CMD можно выбрать Windows-1251/CP866 в анализаторе, если файл получен в этой кодировке; локаль и кодировку записывайте отдельно.

Откройте файл вручную в **Анализаторе**. Лимит — 2 MiB и 50 000 строк. Сначала сверяйте исходный текст и статус разбора, затем наблюдения. `partial` не означает полный разбор. Экспорт модели Workbench не является оригинальным выводом ОС.

## Учебные задания

| Тема           | Эксперимент в VM                                                         | Доказательства и повторная проверка                                                                                               |
| -------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| Адресация      | Сравнить DHCP и статический адрес, неправильный префикс, свободный адрес | Конфигурация до/после, аренда, доступность своего сервиса                                                                         |
| DNS            | Своя запись, кэш, отрицательный ответ, выбор сервера                     | Прямой ответ сервера отдельно от клиентского разрешения                                                                           |
| VPN/маршруты   | Два учебных сегмента и специфичный маршрут                               | Таблица, выбранный next hop, ICMP и нужный TCP-порт                                                                               |
| MTU            | Разные DF-пробы в своём маршрутизируемом сегменте                        | Размер IPv4-пакета, сообщение о фрагментации, повторная передача                                                                  |
| IPv6           | Свои IPv6-адреса и AAAA, link-local с зоной интерфейса                   | Отдельно IPv4/IPv6; ND/SLAAC исследуются средствами ОС                                                                            |
| HTTP/TLS       | Свой тестовый сервер и учебная CA                                        | DNS → TCP → TLS → статус HTTP → операция приложения                                                                               |
| Windows        | Своя тестовая служба, события, ресурсы системы                           | `Get-Service`, выбранные `Get-WinEvent`, состояние диска/процесса; эти форматы сохраняйте как заметки, анализатор их не разбирает |
| AD/SMB/GPO     | Изолированный домен, группы, ресурс и политика                           | DNS/SRV, часы, `klist`, `whoami /groups`, `gpresult /r`, share/NTFS; доменные секреты не экспортируйте                            |
| Linux          | Учебная служба и файл конфигурации                                       | `systemctl status`, `journalctl -u`, `ls -l`, владелец и права; результаты — в отчёте, не в Windows-парсере                       |
| Контейнеры     | Свой Compose web/db, ошибочный адрес зависимости                         | Логи, health check, имя сервиса, порт, контрольная операция                                                                       |
| Git/CI         | Отдельная учебная копия репозитория, два изменения одной строки          | Граф веток, конфликт, согласованный файл, проверка итогового коммита                                                              |
| Восстановление | Копия вымышленных данных в новом окружении                               | Контрольная запись, целостность, измеренные RPO/RTO, работающее приложение                                                        |

Результат каждого задания: симптом → гипотеза → свидетельства → минимальное изменение → повторная проверка → откат/вывод. Введите заметки в портфолио Workbench; свободный текст автоматически не обезличивается.

## Настоящие Windows fixtures для регрессии

Нужно собрать Windows 10/11 и Server, RU/EN, один/несколько адаптеров, VPN, APIPA, отключённый интерфейс, частичный вывод, DNS timeout/NXDOMAIN и успешный ответ. Для каждого примера запишите:

```json
{
  "schemaVersion": 1,
  "origin": "manual-windows-capture",
  "os": "Windows 11 — указать выпуск и build",
  "locale": "ru-RU",
  "shell": "CMD или PowerShell и версия",
  "command": "ipconfig /all",
  "encoding": "UTF-8",
  "conditions": "Только собственная учебная VM; описать адаптеры и неисправность",
  "capturedAt": "Заменить фактической датой ISO 8601",
  "redactions": ["Имена, MAC, домен, реальные адреса заменены согласованно"],
  "expectedStatus": "ok или partial или unsupported",
  "reviewed": false
}
```

Это сопроводительная запись, не импортируемый формат анализатора. Сохраните обезличенный вывод отдельно. Не публикуйте оригинал. Замены должны сохранять взаимосвязи клиента, шлюза, DNS и маршрутов. Ключи, пароли, билеты, cookies и пользовательские файлы не входят в fixture.

После проверки добавьте разрешённый пример в `src/fixtures/`, зарегистрируйте его в соответствующем parser-тесте и проверьте конкретные поля/предупреждения. Запустите `npm run test:coverage`. Реальный fixture помечается реальным только после фактического получения; текущие синтетические примеры не переименовываются в подтверждённые.

Для учебной временной линии преобразуйте разрешённые события вручную в ограниченный JSON из раздела **«События и трассы»**. Произвольные PCAP/EVTX не поддерживаются. Такой пересказ не является доказательством подлинности исходного события.

## Проверка доступности

На настоящем устройстве отдельно пройдите простой ввод с клавиатуры и экранным диктором: название поля, ввод, выполнение, сообщение об окончании, вывод, переключение темы, импорт и отказ импорта. Проверьте мобильную клавиатуру, увеличение масштаба и восстановление сохранений. Автоматическая Axe-проверка дополняет эти действия.

Первичные материалы: [ipconfig](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/ipconfig), [gpresult](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/gpresult), [Kerberos](https://www.rfc-editor.org/info/rfc4120/), [Docker volumes](https://docs.docker.com/engine/storage/volumes/), [Git merge](https://git-scm.com/docs/git-merge). Синтаксис экспорта также описан в [PARSERS.md](PARSERS.md).

## Готовое собственное Linux/HTTP-окружение — 0.6.0

[Два изолированных контейнера](../lab-environments/linux-http/README.md) предоставляют настоящее HTTP-приложение и зависимость, подготовленные отказы прав/готовности, исходное состояние, сброс и ручной перенос отчёта в тот же маршрут навыка. Шаблоны доступны в разделе настоящего стенда. Контейнеры не используют host mounts, root или Docker socket и слушают опубликованный порт только на loopback. Приложение не запускает их автоматически. Для systemd, Windows/AD и TLS используйте соответствующую отдельную VM; контейнерный HTTP-стенд этих функций не заявляет.

[Git-стенд с конфликтом и проверками](../lab-environments/git-ci/README.md) создаётся только в новом каталоге вне существующих репозиториев. Две ветки, исходный тег, проверки содержимого, отмена merge, сравнение с rebase и локальный откат дают воспроизводимый процесс без remote. Шаблон и инструкция также скачиваются в Workbench.

# Учебный терминал

Раздел **«Учебный терминал»**, маршрут `/#/terminal`. Это виртуальная учебная среда Windows на TypeScript и интерфейс xterm.js. Команды не запускаются в ОС пользователя и не отправляют сетевые запросы. После загрузки приложения сервер для лабораторий не нужен.

## Первый запуск

1. Выберите лабораторию: неверный DNS, устаревший DNS-кэш или ICMP/TCP.
2. Выберите режим до первой команды. Для изменения режима начните попытку заново.
3. Введите `help`. Для текстового интерфейса включите **«Простой ввод и текстовый вывод»**. Он также включается, если графический терминал не удалось создать.
4. Исследуйте исходное состояние, затем исправьте виртуальную настройку, если это необходимо.
5. Нажмите **«Разобрать проверку N»**: используются существующие парсеры, объяснения и исходные строки. В нижнем блоке сравните две проверки одной команды.
6. Выберите обоснованный вывод и проверьте решение. Для исправляемых неисправностей требуется TCP-проверка по имени после изменения.
7. При необходимости скачайте разбор или сохраните контрольную точку среды.

Терминальные проверки отделены от рабочего анализатора и его сессий. Переход в учебную среду не заменяет введённые реальные логи. Используйте ссылки уроков и справочника для разбора темы; все данные терминала явно обозначены как учебные.

В продвинутых уроках DNS и TLS есть прямые переходы к соответствующей терминальной практике. Боковое меню, учебный центр и глобальный поиск также открывают лаборатории.

## Режимы

| Режим                    | Подсказки и проверка                                                               | Журнал                                                      |
| ------------------------ | ---------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| Обучение                 | Три последовательные подсказки; неполное решение можно дополнить и проверить снова | Завершённая попытка; каждая подсказка уменьшает оценку на 5 |
| Самостоятельная практика | Справка команд, без подсказок; проверку можно повторить                            | Итог не записывается                                        |
| Проверочная работа       | Справка `help` доступна; одна итоговая проверка завершает попытку даже при ошибках | Итог записывается один раз                                  |

После завершения ввод заблокирован до **«Начать заново»**. Перезапуск означает новую попытку. Баллы отражают выполнение условий конкретной модели, а не профессиональную квалификацию и не защищённый экзамен. JSON контрольных точек редактируется пользователем; сертификаты и доверенная проверка авторства не реализованы.

## Виртуальные узлы

| Узел                   | Значение                                 |
| ---------------------- | ---------------------------------------- |
| ПК                     | TRAINING-PC, Ethernet, InterfaceIndex 12 |
| IPv4 / маска           | 192.0.2.10 / 255.255.255.0               |
| Шлюз                   | 192.0.2.1                                |
| Рабочий DNS            | 192.0.2.53                               |
| DNS без записи портала | 192.0.2.54                               |
| Портал                 | portal.lab.example, 192.0.2.20, TCP 443  |
| Старый адрес портала   | 198.51.100.99                            |

Адреса документационные. В первой лаборатории DNS адаптера установлен на `.54`. Во второй сервер настроен правильно, но кэш содержит старый адрес. В третьей портал принимает TCP 443 и не отвечает на ICMP Echo. Другие TCP-порты портала считаются закрытыми в этой модели.

## Поддерживаемый синтаксис

Регистр имён команд и параметров не важен. Поддержаны пробелы и аргументы в одинарных/двойных кавычках. Одна команда до 512 символов. Конвейеры, скрипты, перенаправления, подстановки и управляющие символы отклоняются. Синтаксис с `-Name`, сокращённые параметры и неописанные варианты не поддерживаются.

| Команда              | Поддерживаемая форма                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------- |
| Справка / очистка    | `help`, `cls`                                                                                   |
| Параметры адаптера   | `ipconfig`, `ipconfig /all`                                                                     |
| Кэш DNS              | `ipconfig /displaydns`, `ipconfig /flushdns`                                                    |
| DNS напрямую         | `nslookup portal.lab.example [192.0.2.53]`; допустим также сервер 192.0.2.54                    |
| ICMP                 | `ping portal.lab.example [-n 1]`; число запросов 1–4                                            |
| Трассировка          | `tracert portal.lab.example`                                                                    |
| Маршруты             | `route print`                                                                                   |
| Клиентский DNS       | `Resolve-DnsName portal.lab.example [-Type A] [-Server 192.0.2.53]`                             |
| TCP                  | `Test-NetConnection portal.lab.example -Port 443`; порт 1–65535                                 |
| Параметры PowerShell | `Get-NetIPConfiguration`                                                                        |
| Изменение DNS        | `Set-DnsClientServerAddress -InterfaceIndex 12 -ServerAddresses 192.0.2.53`; доступен также .54 |

PowerShell-команды с диагностическими результатами здесь сразу выводят выбранный JSON для анализатора. На настоящей Windows для такого формата нужен описанный в [PARSERS.md](PARSERS.md) экспорт через `Select-Object` / `ConvertTo-Json`. Терминал не является полным интерпретатором PowerShell.

`nslookup` читает ответ виртуального сервера напрямую и не меняет настройки или клиентский кэш. `Resolve-DnsName` без `-Server`, `ping`, `tracert` и `Test-NetConnection` используют моделируемое клиентское разрешение с кэшем. Явный `-Server` в Resolve-DnsName обходит этот кэш в модели. Изменение адреса DNS не очищает кэш; `/flushdns` не меняет DNS-сервер.

Числовые IPv4 можно использовать в клиентских проверках. Успех возможен только для известных узлов и поддержанного протокола; это не проверка произвольных адресов. По IP можно подтвердить TCP 443, но такой результат не заменяет повторную проверку по имени при устранении DNS-проблемы.

`ipconfig /displaydns`, изменение настроек и текстовые отказы без адреса не выдаются за поддерживаемую структурированную модель. Для них доступен исходный текст; кнопка разбора есть только для известных форматов. Сравнение PowerShell требует одного cmdlet.

## Клавиатура и доступность

Enter выполняет строку, Backspace удаляет последний символ, ↑/↓ выбирают историю последних 50 команд, Tab дополняет однозначный пример, Ctrl+C очищает текущий ввод. Вставка нескольких строк превращается в одну редактируемую строку и не запускает команды автоматически. Для редактирования внутри строки используйте обычное поле в простом режиме. `cls` очищает экран, но сохраняет результаты проверок и среду.

Размер терминала подстраивается под контейнер. Цвета следуют общей теме, screenReaderMode включён. При уходе со страницы освобождаются terminal, resize/theme observers. Простой режим даёт обычные label/input/button и доступный текстовый вывод. Автоматическая Axe-проверка не заменяет испытания реальными screen reader.

## Данные и восстановление

- Активная среда, последние 40 проверок и выбранный разбор живут в Pinia, сохраняются при навигации и очищаются при перезагрузке. Текстовый экран ограничен 60 000 символами, xterm scrollback — 500 строками.
- **Сохранить контрольную точку** требует отдельного checkbox. Записи нет после каждой команды. В IndexedDB хранится максимум одна точка на каждый из трёх фиксированных ID.
- Точка содержит только состояние модели: публичные адреса из списка, события проверок, ревизию, режим, использованные подсказки, выбранный вариант объяснения и признак завершения. Исходные команды и вывод не включаются.
- Экспорт/импорт JSON версии 1, максимум 8 KiB, строгая Zod-схема. Неизвестные поля, другие адреса/лаборатории, некорректные события и ревизии отклоняются.
- Загрузка/импорт сначала показывают предпросмотр; только **«Восстановить учебную среду»** заменяет попытку. Восстановление не исполняет историю и не начисляет прогресс повторно.
- Контрольная точка удаляется отдельно. Настройки показывают количество сохранений и позволяют очистить временную попытку, оставляя сохранения.
- Итог идёт в существующий прогресс v3 как событие `scenario` с ID `TERM-…`. Формат не изменён, старые данные продолжают читаться. В журнале есть отдельный фильтр терминальных лабораторий, экспорт/импорт прогресса принимает зарегистрированные ID.
- Прогресс постоянно хранится только при включённом общем переключателе. Разбор Markdown не содержит введённых команд. Данные не синхронизируются и не шифруются приложением.

## Архитектура и проверка

`catalog.ts` описывает задания, команды и объяснения. `engine.ts` — чистые immutable переходы виртуального DNS/кэша, генерация вывода и оценка условий. `useTerminalStore.ts` связывает попытку с существующим анализатором и learning store. `TerminalConsole.vue` — только ввод/отображение. `checkpoint.ts` и `repository.ts` проверяют и хранят явные сохранения.

Никаких `eval`, shell/PTY, backend, WebSocket к удалённой консоли, сетевых запросов из обработчиков команд. Ссылки в terminal output не открываются; пользовательский текст не вставляется как HTML. Пакеты `@xterm/xterm` 6.0.0 и `@xterm/addon-fit` 0.11.0 загружаются с маршрутом терминала, не через CDN.

Новые проверки: DNS/cache/ICMP/TCP причины и повторная верификация, генерация разбираемых форматов, семантический diff, отказ скриптов/параметров, границы JSON, одно начисление результата, режимы, сохранение и отсутствие команд в checkpoint. Браузерные сценарии покрывают xterm keyboard/paste, простой режим, три лаборатории, checkpoint/reload, изоляцию рабочего ввода и мобильную доступность.

## Границы и следующие этапы

Не моделируются реальный стек Windows, DHCP-аренды, изменение маршрутов, VPN, IPv6, TTL во времени, задержки/нагрузка сети, HTTP, TLS, службы AD/GPO, произвольные файлы или программы. Tracert и таблица маршрутов — фиксированная небольшая учебная топология. Неизвестные узлы не исследуются в интернете.

Следующий этап: добавить декларативную схему сетевой топологии и условий лаборатории, редактор таких заданий, моделируемый DHCP/маршрутизацию, больше допустимых форм синтаксиса и вариантов неисправностей. Для полной практики настоящей Windows понадобится отдельный изолированный стенд; интерфейс терминала можно переиспользовать, но модель выполнения и инфраструктура будут другими.

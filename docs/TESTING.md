# Проверка проекта

```sh
npm ci
npm run check:quick
npm run check:feature -- workshop
```

Полный набор после каждой правки не нужен. `check:quick` проверяет архитектурные ограничения, lint и типизацию. `check:feature` запускает только тесты выбранной области (`terminal`, `workshop`, `parsers`, `companion`); у companion добавляется проверка HTTP/SQLite. Флаг `--browser` добавляет актуальную сборку и браузерные сценарии области только в Chromium. Например: `npm run check:feature -- terminal --browser`.

## Проверка архитектуры

```sh
npm run check:architecture
node scripts/check-architecture.mjs --report .workbench-data/architecture.json
```

Checker использует TypeScript AST для `.ts/.tsx/.js/.jsx/.mjs` и script-блоков `.vue`, проверяет публичные входы, направления между модулями, слои, runtime-циклы и native Node imports. Его 19 тестов включают lazy/type imports, фасады с транзитивным I/O, обращения к браузерным API через строковые ключи и деструктуризацию, сырые таблицы в UI и запрет feature-зависимостей kernel. Правила и ограничения: [ARCHITECTURE.md](ARCHITECTURE.md).

Тесты workshop находятся рядом с соответствующим слоем; проверки нескольких подсистем — в `src/features/workshop/__tests__`. Чистые парсеры и обезличивание находятся в `src/domain/diagnostics`, поэтому scope `check:feature -- parsers` использует новый путь. Настройки coverage перенесены вместе с исходниками; порог 85% сохранён.

## Точечный разбор DNS-ошибок

`remediation.test.ts`, `remediationStore.test.ts`, `ErrorPracticePanel.test.ts` проверяют новый контекст, сутки до отложенной проверки, повторное назначение после ошибки, неизменяемость первого ответа, дублирующий клик, старые записи/backup, повреждённый или преждевременный импорт, opt-in и отказ сохранения. `ContinueLearning.test.ts` дополнительно проверяет немедленное назначение новой ошибки без ожидания минутного таймера.

`e2e/remediation.spec.ts` использует настоящий IndexedDB и проверяет ошибку урока → продолжение после reload → общий backup и восстановление; переход на следующий день с тестовыми часами и скрытым разбором; работу только в памяти. Новый экран проверяется на 320 px и серьёзные/критические нарушения Axe. Файл включён в `check:feature -- workshop --browser`.

```sh
npm run check:quick
npm run check:feature -- workshop
npm run build
npm exec --no -- playwright test e2e/remediation.spec.ts --project=chromium --project=webkit
```

Фактический протокол текущего этапа — [VALIDATION.md](VALIDATION.md). Windows captures и ручная проверка экранного диктора остаются отдельными проверками.

Для одного файла: `npm run test:unit -- networkEngine.test.ts`; для наблюдения за изменениями: `npm run test:watch -- networkEngine.test.ts`. `npm run test:changed` выбирает тесты по Git-изменениям и статическим зависимостям. Это вспомогательный локальный фильтр: для новых файлов, динамических зависимостей и общих настроек выбирайте область явно.

| Изменение                              | Локально                                                              |
| -------------------------------------- | --------------------------------------------------------------------- |
| Документация                           | Prettier изменённых файлов и ссылки                                   |
| Отдельная логика                       | Тесты функции и связанных контрактов, типизация                       |
| Экран                                  | Быстрые проверки и соответствующие сценарии Chromium                  |
| Сохранения/миграции/офлайн/зависимости | Браузерные проверки затронутого процесса; полный набор перед выпуском |

Полный контроль: `npm run check:full` (нужны установленные Chromium/Firefox/WebKit). GitHub CI по-прежнему выполняет форматирование, lint, coverage, companion, сборку с типизацией и все браузеры. `npm run check` оставлен для совместимости. Pages требует успешный CI ровно этого коммита в main и затем только пересобирает его из lockfile — тесты второй раз не запускаются. Правки workflow сами по себе не запускают публикацию.

`evolution.spec.ts` — четыре новых сценария: визуальные конструкторы; backup/CAS/поздний отказ транзакции; инцидент с несколькими узлами; перенос прежнего журнала и самостоятельные записи стенда. Отказ транзакции создаётся только тестом, после записи коллекций: проверяется сохранность прежнего содержимого, затем успешное восстановление.

Команды фильтрации: [Vitest CLI](https://vitest.dev/guide/cli.html), [Playwright](https://playwright.dev/docs/running-tests). Проверка конкретного SHA: [GitHub Actions API](https://docs.github.com/en/rest/actions/workflow-runs).

Для выборочной проверки исправленных сбоев Firefox после актуальной сборки:

```sh
npx playwright test e2e/terminal.spec.ts e2e/evolution.spec.ts --project=firefox --grep "xterm keyboard|terminal lab works offline|complete backup" --retries=0
```

Это четыре сценария: вставка, два пути офлайн-терминала и резервная копия. Для сравнения доступны `--project=chromium --project=webkit`. Ожидание `load` после `reload()` не означает готовность первоначальной lazy-навигации Vue: перед последующим переходом проверяется заголовок страницы, а перед отключением сети — активный контроллер Service Worker. Офлайн-терминал также полностью перезагружается без сети. Искусственная вставка использует явно заданный `clipboardData.getData`, поскольку синтетический DataTransfer Firefox не обеспечивает тот же payload. Тест проходит через настоящий обработчик xterm и сохраняет проверку ручного Enter.

Тесты используют синтетические fixtures. Unit проверяет октеты, IPv6, маски, /0, /31, /32, локали, продолжения, evidence, неполный вывод, детерминизм, неизменность моделей и отсутствие ложных диагнозов. Также проверяются longest-prefix routes, корреляция времени, семантический diff CMD и новых DNS/PowerShell моделей, неоднозначные интерфейсы, целостность строк маршрутов, приватность сессионного отчёта, round-trip экспорта частями, строгий учебный импорт и прогресс. Coverage ограничен выбранной чистой логикой; минимальный общий порог 85% по строкам, statements, functions и branches.

Component проверяет ограничения, текстовый XSS-safe вывод и отмену позднего чтения файла после очистки/нового ввода/ухода со страницы. Тесты расширений проверяют модели команд, импорт кейсов и все шесть сценариев тренажёра.

Worker lifecycle проверяется fake Worker: поздние ответы старого экземпляра игнорируются; отказ конструктора обрабатывается явной ошибкой.

Playwright запускает production preview и статический сервер с `/preview/site/` без SPA rewrites. Проверяет пять форматов, evidence, скачивание, отсутствие запросов вне origin и localStorage/sessionStorage для обычного анализа, очистку/reload, файлы, raw consent, Escape, skip link, темы и мобильный viewport. Явное сохранение кейсов проверяется на persistence, comparison, import preview и удаление. Синтетический `ping` с 30 000 ответов проверяет реальный worker и пагинацию.

Локально и в CI используются два параллельных worker. Проверки новых экранов на доступность параметризованы по маршруту: каждый экран получает собственный лимит времени. При 1280×900 дополнительно проверяется полная видимость нижнего пункта меню.

Новые сценарии: согласованная сессия из четырёх проверок, private diff/export, reload; opt-in прогресс и повторение ошибок; чек-лист export/reset; глобальный поиск с клавиатуры; выбор маршрута и evidence; переименование/фильтры/сортировка дат. Офлайн-сценарии с корня и подпапки проверяют отсутствие автоматической регистрации, только статические файлы в Cache Storage, отсутствие marker пользовательского источника, reload и разбор Worker без сети, ленивый учебный раздел и отключение регистрации. `test:e2e` запускает Chromium, `test:e2e:all` — Chromium/Firefox/WebKit; CI использует второй вариант.

Версия 0.3: `clarity.spec.ts` проверяет обязательные ответы помощника, вариант Wi-Fi, USB-принтер, экспорт отметок, передачу контекста, сохранность введённого текста и плана между разделами, сброс при reload/очистке. Также проверяются краткий разбор → evidence, поиск термина с клавиатуры, рекомендация темы по ошибке, запуск конкретного сценария, проверка/повтор задачи по подсетям и защита от случайной замены текста учебным примером. Офлайн-проверки включают помощник и практику подсетей с корня и подпапки.

Новая чистая логика тестируется на всех комбинациях ответов помощника, валидности ссылок на каталог, неизвестных ID, безопасном экспорте, статусах DNS/ICMP/маршрута, приоритете наблюдений и границах evidence. Маршрут учитывает исправленный ответ и завершённые темы. Задания по подсетям проверяются на независимых ожидаемых значениях, некорректном формате и случаях /31, /32.

Продвинутый курс: `academy.spec.ts` проверяет подсказку, неизменность первого выбора, объяснение ошибочного решения и Markdown-разбор лабораторной; импорт v1, повторение продвинутого вопроса, экспорт v3 и сохранность после reload; переходы из справочника/поиска и все восемь уроков при 360 px с широким шрифтом. Unit-тесты проверяют целостность каталога и предпосылок, интервалы 1/3/7/14/30 дней, сброс серии, приоритет ошибок, ранние ответы, неверные даты/ID и миграцию без выдуманных дат. Импорт реактивного предпросмотра проверяется на отсутствие ошибки клонирования и независимость данных. Отложенные записи проверяют, что статус сохранения остаётся активным до завершения всей очереди; e2e ждёт подтверждения записи перед reload.

Офлайн-сценарии в `growth.spec.ts` дополнительно открывают продвинутый курс и TLS-лабораторную без сети, показывают подсказку и отвечают на вопрос. Проверяются корень и `/preview/site/`; внешние источники при этом не открываются.

Axe проверяет serious/critical accessibility violations на маршрутах в обеих темах, после анализа и в отчёте. Автоматическая проверка не заменяет полную оценку WCAG и screen reader.

Coverage включает domain/parsers/export, сессии, планы помощника, краткие объяснения, маршрут и практику подсетей, расписание повторений и логику лабораторных, выбранные чистые модули кейсов/обучения/тренажёра/чек-листов. Это не процент всего приложения. Итоговый протокол — [VALIDATION.md](VALIDATION.md). Для двух доступных локально движков: `npm run test:e2e:all -- --project=chromium --project=webkit`.

Локальная зелёная проверка не означает успешный GitHub Actions run или публикацию Pages. Эти состояния подтверждаются отдельно для опубликованного коммита. Сетевые устройства и корпоративные интеграции не проверяются приложением.

## Новые учебные функции и архив

`terminal.spec.ts` проверяет три лаборатории с вводом команд, реальное keyboard/paste взаимодействие xterm.js, JSON-контрольные точки и отсутствие исходных команд в них, неизменность рабочего ввода анализатора, сохранение прогресса после reload, fallback при отказе графического компонента, мобильную доступность и офлайн с корня/подпапки. Новые unit-тесты проверяют причинную связь DNS/кэша/ICMP/TCP, повторную верификацию после изменения, генерацию поддержанных форматов, границы команд/JSON и одно начисление результата. Coverage включает чистый терминальный движок и парсер checkpoint. [Поддерживаемые формы и ограничения](TRAINING_TERMINAL.md).

`development.spec.ts` проверяет самостоятельный ответ и неизменность попытки, opt-in журнал/цель после reload, новые форматы через реальный worker, приватность DNS/TXT-отчёта, создание/сохранение/прохождение собственного двухэтапного инцидента, отказ неверного импорта, явное сохранение архива и восстановление сравнения без исходника. Новые страницы проверяются на 360 px, Verdana и обе темы с Axe.

Unit-тесты дополнительно проверяют типы и границы DNS/PowerShell, физические строки вложенного JSON, отказ неполных блоков и несовместимых семейств адресов, 24 самостоятельных задания, миграцию v2 без истории, локальную неделю, лимит 500, редактор и квоты, whitelist архивов всех семи форматов, стабильность маркеров/отношений TXT, неизменность исходных моделей и запрет смешивания архива с новыми измерениями. Хранилища IndexedDB проверяются реальными браузерными сценариями; чистые расчёты квот — unit.

## Практикум и companion 0.4.0

`networkEngine.test.ts` проверяет полное решение 20 новых моделей с исходным evidence и целевой проверкой, IP/маршруты/метрики/VPN/кэш/TTL/MTU, все генерируемые диагностические форматы, неправильные формы и отсутствие изменений при отказе, строгий checkpoint и воспроизводимость вариантов. Аудит/откат проверяет сохранение ошибки и времени, истечение кэша и обязательную новую верификацию.

`workshop.test.ts` проверяет разделение чтения/базовых знаний/самостоятельных вариантов, повторение, все предпосылки пяти траекторий, готовность к настоящему стенду без выдуманной терминальной квалификации, целостность курсов/ссылок, графы и ограниченные трассы. `customCourses.test.ts` проверяет строгие пакеты, unsafe sources, повторяющиеся ID и ссылки. CSP origins проходят отдельные проверки против wildcard/injection и credentials. Coverage включает эти выбранные чистые модули, а не все Vue-компоненты и хранилища.

`workshop.spec.ts` проверяет opt-in/быстрый reload/opt-out, авторскую лабораторию, TLS/портфолио, граф Git, скрытый импорт трассы, мобильный Axe, редактирование курсора, конфликт вкладок, группу преподавателя, explicit companion UI/CSP, восстановление удалённого авторского шаблона из checkpoint, авторские курсы без изменения встроенных оценок и откат с новой проверкой. IndexedDB проверяется браузером. Для имеющихся движков: `npm run test:e2e:all -- --project=chromium --project=webkit` после сборки.

`npm run test:companion` отдельно запускает Node HTTP/SQLite на случайных loopback-портах с временными базами. Проверяются аккаунты/изоляция/токены/удаление, строгая схема/лимиты, обязательный If-Match/CAS, CORS, версии DB и mocked AI (согласие, payload, квота, ошибки/лимит ответа). Реальных запросов внешнему AI нет. Эти тесты включены в CI и проверки ручной публикации; сервис на Pages не развёртывается.

Результат новой проверки, покрытие, Firefox/macOS и внешние ограничения записаны в [VALIDATION.md](VALIDATION.md). Windows VM/captures и ручной screen reader пока не проверены; подготовлены [инструкции стенда](REAL_LAB.md).

## Регрессии 0.6.1

`auditFixes.test.ts` проверяет продвижение без ожидания mastery, достижимую отложенную проверку после исчерпания причин, хронологию импортов, ссылки на конкретный пакет, предметные формы для всех навыков и новую рубрику инцидентов. `e2e/audit-fixes.spec.ts` проверяет настоящие IndexedDB вкладки, один guard/согласованность URL, возврат сохранённого и текущего разбора, уход из его объяснения и конкретные финальные задания. Этот файл включён в `check:feature -- workshop --browser`.

`npm run test:lab:linux` отдельно проверяет настоящий compose.yaml в уникальном временном проекте, без host volumes и опубликованных портов; исходник сохраняется при восстановлении в отдельную цель. Docker Engine должен быть запущен. Скрипт очищает только свой проект и фиксирует среду.

`npm run test:fixtures:real` строго требует реальные разрешённые обезличенные captures. При пустом manifest выходит с кодом 2, а общий unit-набор явно пропускает настоящую матрицу. [Порядок сбора, ожидаемые модели и ограничения](REAL_FIXTURES.md).

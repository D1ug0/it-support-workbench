# Аудит и следующий этап развития

Дата: 10.10.2026. Исходная версия: `0.5.0`, коммит `f406733`.

Код приложения в ходе этого аудита не изменялся. Изучены учебные процессы, движок терминала, оценивание, хранилища, резервные копии, companion и CI. Выполнены короткие изолированные воспроизведения, без полной тестовой матрицы и без обращения к пользовательской IndexedDB. Визуальная проверка интерфейса, настоящий Windows/Linux-стенд и публичный нагрузочный аудит не выполнялись.

Последний [GitHub CI для f406733](https://github.com/D1ug0/it-support-workbench/actions/runs/38069374385) завершился успешно. `npm audit --omit=dev --json` сообщил **0 известных уязвимостей рабочих зависимостей** на дату проверки. Это результат проверки опубликованных advisories, а не доказательство отсутствия любых ошибок безопасности. Зависимости разработки этой командой не оценивались.

В проекте уже есть терминал, 24 лаборатории, курсы, маршруты навыков, конструкторы, расследования, резервирование и задания стенда. Следующий этап должен повысить достоверность результатов и надёжность этих процессов. Подтверждённых P0 в пределах проведённого анализа не установлено.

## 1. Исправления, необходимые первыми

P1 — сбой результата, восстановления или достоверности завершения. P2 — качество процесса и устойчивость при дополнительных условиях. A07 применяется при использовании опционального companion.

### A01 · P1 · Перезапуск лаборатории во время завершения

**Подтверждено изолированным воспроизведением.** `finish()` получает оценку, ждёт запись практикума, а затем снова читает изменяемые `environment`, `mode` и `feedback`. За это время `start()` может очистить feedback. Результат воспроизведения: `Cannot read properties of undefined (reading 'score')`. Кнопка «Начать заново» не учитывает запись практикума.

Основание: [useTerminalStore.ts](../src/features/terminal/useTerminalStore.ts), функции `finish` и `start`; [TerminalPage.vue](../src/pages/TerminalPage.vue), кнопка перезапуска.

**Правка:** фиксировать ID попытки, лабораторию, режим и результат до первого await; защищать поздние ответы идентификатором попытки; явно показывать состояние завершения. Разделить результат задания и успешность его сохранения.

**Готово, когда:** быстрый перезапуск/смена задания при задержанной записи не вызывает исключений и не присваивает результат новой лаборатории; повторное завершение не дублирует событие.

### A02 · P1 · Восстановление при повреждённом текущем прогрессе

**Подтверждено цепочкой вызовов в коде; браузерное воспроизведение ещё требуется.** Предпросмотр исправной копии вызывает `backupToken()`, а тот — `readProgress()`, который строго разбирает текущее сохранение. Повреждённая базовая запись может блокировать сам предпросмотр восстановления. Также удаление прежней записи обусловлено наличием нового record, а не во всех случаях подтверждённым валидным state.

Основание: [BackupPanel.vue](../src/features/workshop/BackupPanel.vue), `read`; [backupRepository.ts](../src/features/workshop/backupRepository.ts), `backupToken`; [repository.ts](../src/features/learning/repository.ts), `readProgress`.

**Правка:** отдельный путь восстановления, способный получить токен исходных записей без обязательного успешного разбора повреждённого прогресса. Предлагать сохранение повреждённой копии отдельно, не затирать её автоматически. Прежнее хранилище очищать только после проверки пригодности перенесённой записи.

**Готово, когда:** исправный backup восстанавливается при повреждённом baseProgress и прежней записи; ошибка миграции не удаляет последнюю пригодную копию; отказ транзакции оставляет прежние данные.

### A03 · P1 · Допустимые данные могут стать слишком большими для backup

**Подтверждено на синтетическом наборе.** Двадцать допустимых курсов проходят `backupSchema`, но JSON занимает **2 331 561 байт** при лимите **2 097 152 байта**. `parseBackup()` отклоняет его. Экспорт перед скачиванием тоже вызывает этот разбор, поэтому пользователь может сохранить допустимые материалы и затем не суметь сделать общую копию.

Основание: [customCourses.ts](../src/features/workshop/customCourses.ts), [backup.ts](../src/features/workshop/backup.ts), [BackupPanel.vue](../src/features/workshop/BackupPanel.vue), `exportBackup`.

**Правка:** согласовать ограничения коллекций и максимальный размер общего пакета; считать размер UTF-8 до экспорта; обеспечить путь резервирования любого разрешённого набора. Сначала использовать один ограниченный пакет с обоснованным бюджетом; многочастный формат вводить при подтверждённой необходимости. Сохранить защиту от чрезмерного импорта.

**Готово, когда:** любой набор, который приложение позволяет сохранить, можно экспортировать и восстановить; превышение бюджета объясняется до накопления непереносимых данных.

### A04 · P1 · Общая учебная копия не охватывает все авторские задания

**Подтверждено кодом.** Линейные авторские инциденты старого тренажёра находятся в `it-support-workbench-scenarios`. Общая копия читает только семь таблиц БД практикума. В перечне исключений интерфейса эти инциденты не названы. При переносе одной общей копии в чистый браузер они не перенесутся.

Основание: [customRepository.ts](../src/features/simulator/customRepository.ts), [backupRepository.ts](../src/features/workshop/backupRepository.ts), [BackupPanel.vue](../src/features/workshop/BackupPanel.vue).

**Правка:** включить авторские инциденты в следующую версию учебного backup. Для атомарного восстановления предварительно совместимо перенести эту учебную коллекцию в общую БД, с проверкой записей и повторяемой миграцией. Пока переноса нет, явно перечислять исключение и отдельный экспорт.

**Готово, когда:** перенос в чистый профиль сохраняет все авторские учебные материалы; старые пакеты поддерживаются; миграция не теряет исходную коллекцию и не перезаписывает конфликтующие материалы молча.

### A05 · P1 · Лимит переходов считается завершением расследования

**Подтверждено на валидном графе.** После сорока полезных переходов по циклу получено `{ finished: true, node: 'start', score: 100 }` без достижения END. Интерфейс показывает «Сценарий завершён» и 100/100, добавляя примечание о лимите.

Основание: [graph.ts](../src/features/workshop/graph.ts), `chooseGraph`; [GraphEditor.vue](../src/features/workshop/GraphEditor.vue).

**Правка:** разделить состояния `completed`, `limit-reached`, `abandoned`. Оценивать достижение учебных целей и доказательств, а не только долю действий с useful=true. Предотвратить получение баллов повторением одного перехода.

**Готово, когда:** исчерпание лимита не засчитывается как успешное решение; полезный цикл не даёт 100 баллов; предусмотренный путь к END завершается с объяснимой оценкой.

### A06 · P1 · Ошибка сохранения практикума не видна в терминале

**Подтверждено кодом интерфейса и store.** `persist()` практикума записывает ошибку в `workshop.error` и возвращает обработанную очередь. Терминал показывает `learning.error` и `learning.saving`, но не состояние записи практикума. Результат может выглядеть завершённым без понятного сообщения о невозможности его сохранить. Два журнала имеют отдельные переключатели; текст о самостоятельной практике описывает только базовый журнал.

Основание: [useWorkshopStore.ts](../src/features/workshop/useWorkshopStore.ts), `persist`; [useTerminalStore.ts](../src/features/terminal/useTerminalStore.ts), `finish`; [TerminalPage.vue](../src/pages/TerminalPage.vue).

**Правка:** явный результат операции сохранения, единое понятное отображение обоих журналов и их согласий. При конфликте вкладок предложить экспорт текущей попытки и перечитывание, при quota — очистку выбранных данных. Не считать обработанный exception подтверждением записи.

**Готово, когда:** ученик различает «решение выполнено», «результат в памяти», «результат сохранён» и «сохранение не удалось»; ошибки не требуют поиска другого экрана; исходные диагностические данные не начинают сохраняться автоматически.

### A07 · P1 для companion · Некорректный URL выходит из обработки ошибок

**Подтверждено на одноразовом companion с `:memory:` и случайным loopback-портом.** Разбор URL находится перед try/catch асинхронного обработчика. Некорректный request-target вызвал unhandled rejection `Invalid URL`. При стандартном поведении Node это может завершить процесс. Основное статическое приложение этот обработчик не использует.

Основание: [companion.mjs](../server/companion.mjs), строка разбора `req.url` перед try/catch.

**Правка:** включить разбор URL в контролируемую обработку ошибок; вернуть ограниченный ответ 400 и безопасно завершить запрос. Не включать стек или конфигурацию в ответ.

**Готово, когда:** после некорректного запроса процесс продолжает отвечать на health и обычный авторизованный запрос.

## 2. Исправления для качественного повседневного процесса

### A08 · P2 · Пустое портфолио и отсутствие редактирования отчёта

**Пустой отчёт подтверждён воспроизведением:** schema принимает пустые symptom/hypothesis/evidence/change/verification даже с score=100. UUID вычисляется вместе с полями формы; изменение заметок создаёт новый объект, а явного процесса редактирования сохранённого отчёта нет.

Основание: [portfolio.ts](../src/features/workshop/portfolio.ts), [InvestigationPanel.vue](../src/features/workshop/InvestigationPanel.vue).

**Правка:** различать черновик и законченный отчёт; требовать содержательные поля для законченного; фиксировать ID черновика; добавить редактирование и версию отчёта. Связывать выбранные синтетические доказательства с ID команды и ревизией среды. Реальные логи добавлять только явным действием и с предпросмотром.

**Готово, когда:** пустая запись не выглядит законченной работой; исправление заметок не плодит копии; понятно, чем подтверждается вывод.

### A09 · P2 · Неодинаковое поведение при повреждении отдельных записей

При initialize практикум использует safeParse и пропускает отдельные повреждённые материалы. `reloadSaved()` использует строгий parse для каждой коллекции: одна неподдерживаемая запись может оборвать перечитывание всех остальных. Аналогично listScenarios разбирает весь массив через map(parse).

Основание: [useWorkshopStore.ts](../src/features/workshop/useWorkshopStore.ts), `initialize`/`reloadSaved`; [customRepository.ts](../src/features/simulator/customRepository.ts), `listScenarios`.

**Правка:** общий загрузчик коллекций с результатом «валидные записи / проблемные записи / ошибка доступа». Не удалять проблемные материалы; предложить их отдельный экспорт и восстановление. Сохранять ссылочную целостность курсов.

**Готово, когда:** один повреждённый курс или сценарий не скрывает все исправные материалы; пользователю видно, что именно не прочиталось.

### A10 · P2 · Черновики, место хранения и обновления

Формы расследования и самостоятельного стенда живут в памяти, а защиты перехода при несохранённых изменениях в src не найдено. Подробные заметки можно потерять при смене раздела. Отсутствует общий индикатор оценки объёма/persistent storage.

**Правка:** предупреждение при уходе с изменённой формы, ручное сохранение учебного черновика с согласием, продолжение конкретной попытки. В настройках показать origin, состояние хранилища, дату последнего экспорта и последствия очистки. Предлагать persistent storage только явно: IndexedDB по умолчанию использует best-effort хранение, а квота и удаление зависят от браузера. [Основание: MDN Storage API](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

**Готово, когда:** ученик понимает, что останется после reload/очистки/смены браузера; отказ сохранять черновик не блокирует работу; обновление приложения не уничтожает текущую попытку молча.

## 3. Улучшения, которые сделают обучение профессиональнее

### B01 · Высокий приоритет · Достоверная карта навыков

Сейчас variant меняет адрес клиента, сохраняя причину и общий способ решения. skillStatus считает две различные variantKey достаточными для «Самостоятельного владения». Изолированная проверка подтверждает такой результат для двух попыток одного инцидента с разными адресами. Это полезная тренировка переноса параметров, но слабое подтверждение широкого владения темой. В курсе один контрольный вопрос записывает boolean assessment всего навыка.

Основание: [labDefinitions.ts](../src/features/terminal/labDefinitions.ts), `variant`; [skills.ts](../src/features/workshop/skills.ts), `skillStatus`; [WorkshopPanel.vue](../src/features/workshop/WorkshopPanel.vue), `answer`.

**Нужно:** учитывать семейство причины и проверяемые компетенции, разделять перенос параметров и новый диагностический сценарий. Раздельные результаты теории, самостоятельного решения и подтверждённой практики стенда. Несколько форм проверки: выбор гипотезы, расчёт, объяснение противоречия, практическое решение. Проверять сохранение знания позднее на незнакомом варианте. Существующий механизм повторения связать с конкретными ошибками практикума.

**Критерий:** две косметические вариации одного задания не закрывают весь навык; карта объясняет, какие компетенции подтверждены и какие ещё требуют практики.

### B02 · Высокий приоритет · Сквозные профессиональные инциденты

Добавлять законченные задачи на 30–90 минут: уточнение заявки → масштаб отказа → гипотезы → доказательства → минимальное изменение → проверка пользовательского сценария → откат или эскалация → отчёт.

Первая серия:

1. Портал недоступен только у части клиентов: DNS-кэш, путь и независимая неисправность сервиса.
2. TCP доступен, API возвращает 503: зависимости приложения, readiness и журнал.
3. Ресурс SMB недоступен части пользователей: группы, права и обоснованная эскалация; детали AD проверять позже на собственном Windows-стенде.
4. Восстановление сервиса из копии: проверка содержимого, зависимости, измерение длительности и допустимой потери данных.

**Нужно:** цели и ограничения вместо готового диагноза, несколько допустимых путей решения, неизвестные заранее исходные данные, оценка обоснованности изменений. Не начислять результат только за выбор известной причины.

**Критерий:** ученик может решить незнакомый вариант, объяснить каждое изменение и подтвердить восстановление пользовательского сценария.

### B03 · Высокий приоритет · Единый учебный процесс

Маршруты и рекомендации уже есть. Но базовые вопросы, academy, самостоятельная практика, линейный тренажёр, графы, терминал и стенд используют разные формы попыток и прогресса.

**Нужно:** один вход «Продолжить обучение» с сегодняшней задачей, временем, предпосылками и ожидаемым результатом; связи существующих модулей через компетенции и ID попытки. После ошибки вести к конкретному объяснению и упражнению, затем возвращать в исходную задачу. Совместимо сохранять старые результаты, не пересчитывая их в более сильную квалификацию автоматически.

**Критерий:** ученик проходит тему от объяснения до самостоятельного инцидента и отчёта без выбора между несколькими несвязанными журналами.

### B04 · Высокий приоритет · Достоверность материалов и границы модели

Реальные Windows captures пока не получены. Синтетические fixtures проверяют логику на подготовленных форматах, но не устанавливают совместимость со всеми версиями ОС и локалями. Некоторые темы в сети представлены условными флагами — например, IPv6-компонент и права доступа.

**Нужно:** карточка материала с источниками, датой проверки, ОС/версией/локалью, предпосылками и ограничениями. Явно отмечать «команда поддержана симулятором», «результат подтверждён реальным fixture», «теория для внешнего стенда». Ввести матрицу поддерживаемых форматов и разрешённые обезличенные captures с будущего стенда. Каждому новому формату — минимальный пример, проблемный пример и критерий partial parse.

**Критерий:** материалы не создают ложного впечатления, что синтетическая среда воспроизводит все детали Windows/Linux; совместимость указана по фактическим проверкам.

### B05 · Средний приоритет · Терминал из одного реестра команд

Tab в TerminalConsole берёт commandExamples, а команды расширенной модели и дополнительные узлы перечисляются отдельно. Учебный справочник, автодополнение и обработчик могут расходиться.

Основание: [TerminalConsole.vue](../src/features/terminal/TerminalConsole.vue), ветка Tab; [commandRegistry.ts](../src/features/terminal/commandRegistry.ts); [networkEngine.ts](../src/features/terminal/networkEngine.ts).

**Нужно:** единый реестр поддерживаемых форм, параметров, целевого узла, платформы, чтения/изменения и необходимых прав. Из него формировать help, подсказки и дополнение. Различать Windows PowerShell, PowerShell 7 и Linux, не показывая все команды как одну реальную оболочку. Поддерживать дополнительные формы только вместе с семантикой модели.

**Критерий:** доступная в help форма работает и дополняется; неподдержанный параметр объясняется конкретно; пример не выдаётся за произвольное исполнение команд ОС.

### B06 · Средний приоритет · Переход от симуляции к настоящему стенду

Шесть заданий стенда уже есть. Следующий полезный шаг — воспроизводимые учебные окружения, подготовка исходного состояния, снимок/сброс, разрешённый сбор вывода и перенос отчёта в тот же маршрут навыка.

**Нужно:** начать с доступного пользователю Linux/Git/HTTP окружения; Windows/AD добавить после появления собственной VM. Кнопка запуска настоящей оболочки, если понадобится, должна работать через отдельный ограниченный исполнитель учебного окружения с явным выбором цели. Не расширять обычный companion до исполнения произвольных команд на хосте.

**Критерий:** ясно видно, где симулятор, а где реальная ОС; воспроизводимое задание можно безопасно сбросить; самостоятельный отчёт не выдаётся за автоматическую аттестацию.

## 4. Порядок работ и проверки

1. **Надёжность:** A01, A02, A03, A05, A06; A07, если companion используется. Для A04 сначала совместимая миграция, затем новый формат backup.
2. **Повседневная работа:** A08–A10, согласование двух журналов и обновление фактической документации.
3. **Обучение:** B01 + B03 и один сквозной инцидент B02. Проверить его полезность до добавления остальных пакетов.
4. **Глубина:** B04–B07 по выбранному направлению; эксплуатация companion и AI — при реальной потребности.

Проверять по затронутому процессу. Для воспроизведённого сбоя — одна регрессия, проверяющая последствие. Для миграций/backup — сохранность данных при отказе и один целевой браузерный процесс. Для изменения команд/оценки — чистая логика и соответствующая лаборатория. Полную браузерную матрицу и coverage оставлять GitHub CI; локально не повторять их после каждой небольшой правки. Предыдущий успешный CI не заменяет проверки будущих изменений.

Первый запрос на реализацию можно сформулировать так: **«Исправь A01–A06 из NEXT_IMPROVEMENTS_AUDIT.md, сохрани совместимость старых данных и запусти только необходимые проверки»**. A07 добавить при использовании companion. Остальные пункты остаются отдельными законченными этапами.

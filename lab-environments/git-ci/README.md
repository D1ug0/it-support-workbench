# Настоящий Git и локальные проверки

Предпосылки: Git и Node.js 22.22+/24, новый каталог вне рабочих репозиториев. `create.mjs` создаёт только вымышленную конфигурацию и локальную историю, не подключает remote. Идентификатор автора задаётся для команд этого стенда; глобальные настройки Git не меняются.

Сохраните скачанные `create.mjs` и этот файл рядом. Подготовка:

```sh
node create.mjs /private/tmp/workbench-git-case
cd /private/tmp/workbench-git-case
git status
git log --oneline --graph --all
node check.mjs
git merge retry-policy
```

Проверка `main` падает из-за одной попытки; merge создаёт конфликт двух строк конфигурации. Сформулируйте гипотезу, сравните обе версии через `git show main:config.json` и `git show retry-policy:config.json`, решите конфликт по требованиям приложения. Требования находятся в `check.mjs`: timeout от 5 до 10 секунд, retries=2. Затем выполните `node check.mjs`, проверьте `git diff --check`, сохраните решение локальным коммитом и объясните граф истории.

До коммита можно отменить именно начатое слияние через `git merge --abort`. Для сравнения merge/rebase создайте второй стенд с другим новым путём и выполните `git switch retry-policy`, затем `git rebase main`. Объясните изменение родителей и необходимость повторной проверки содержимого. Локальный release обозначьте тегом только после успешной проверки; тренировку отката выполняйте через `git revert` собственного итогового коммита с повторной проверкой. Remote/push для задания не нужен.

Снимок начального состояния отмечен `lab-start`. Безопасный сброс — создать новую папку через `create.mjs`; скрипт отказывается перезаписывать существующий каталог. Для незнакомой итоговой работы партнёр меняет одну из конфигураций, не меняя проверок; вы исследуете diff и проходите изменение заново. В отчёт стенда перенесите версии Git/Node, команды, конфликт, гипотезы, результаты проверок и итоговый граф. Это реальная локальная работа Git; GitHub Actions здесь не запускается и автоматической аттестации нет.
